# Area 7: Security and Privacy — ProCyclingResults

Assessed commit: `9dc326f` (worktree copy). Date: 2026-09-26. Production: https://procyclingresults.up.railway.app. Line numbers refer to `server.js` unless another file is named.

## 1. Summary

Overall grade: **B**. The fundamentals that matter for a site of this shape are right: every HTML builder I checked escapes upstream text, the JSON block embedded in the page escapes `<`, every request-driven fetch is keyed to a race already in the payload rather than to a caller-supplied title, the editor token is compared in constant time from a header, the body is capped, the file path is fixed, no request is logged, and the git history holds no secret. The risk that matters most is availability on a single instance with no rate limiting: `/` is re-rendered from cached data on every request and `/api/races` is pretty-printed on every request, `/api/race-news` can trigger up to 32 Bing searches per race per 15 minutes, and `/api/race-stages` does not de-duplicate concurrent first requests for the same race, so a small loop from one client can pin the CPU and spend the site's standing with its sources. Second is the editor's key handling: the key sits in `localStorage` on a page that also loads a third-party analytics script, there is no throttle on failed attempts, and the GitHub token behind it can write any path on `main`, which Railway deploys, so its scope needs checking. The production response carries no security headers at all (no HSTS, CSP, `nosniff`, frame-ancestors or Referrer-Policy); Railway adds only its own routing headers. Nothing here is an emergency and nothing needs fixing this week; the headers and the `localStorage` change are an hour's work and worth doing this month, and the GitHub token scope is a five-minute check.

## 6. Strengths

- Zero third-party runtime dependencies (`package.json`); CI runs `node -c server.js` and the test suite on Node 22.
- Escaping is consistent: every builder inspected wraps upstream text and attribute values in `escapeHtml` (1425–1432), the rider index is embedded with `<` escaped to `<` (927–930, tested at test 2084–2087), and the client hover card escapes again before `innerHTML` (15942–15948). All other client `innerHTML`/`outerHTML` sinks take same-origin server HTML only.
- Request-driven fetches cannot be aimed: `/api/race-news` and `/api/race-stages` look the id up in the current payload (17018–17024, 6845–6855) and nonsense ids answer `404` in 0.2 s with no upstream call (probes 2–3); `group` is a `Set` lookup (16987–16998); `/api/site-content` writes only to a fixed two-entry file map (16166–16181, 16357–16364).
- The editor: bearer token in a header, never a query string; SHA-256 then `timingSafeEqual` (16374–16378) so length is not leaked; auth checked before the body is read; 256 KB body cap with `request.destroy()` (16434–16450); the token never appears in any response or page (grep: 16238, 16366, 16459–16462, 16515 only); failures return a fixed message; unit tests cover the compare and the markdown subset (test 5767–5817); markdown is escaped before rendering, so raw HTML is impossible and `javascript:` links stay text.
- Privacy: no request logging at all (only the startup line, 17111); the contact address is reported only as `configured`/`not set` (22); links out carry `rel="noreferrer"`; the outbound user agent names a public policy document.
- Caches are bounded by known race ids: `stageHistoryCache` capped at 40 (6818), `wikiRawCache` pruned after a day idle (2403–2407), Wikipedia limited to 3 concurrent fetches with `maxlag` (120, 1850–1862), every fetch has a 10 s timeout and two retries (121, 125).
- Organiser video URLs are pinned to the organiser's host (6207, 6221); race and rider links are built from slugs and `encodeURIComponent`, never from raw upstream URLs.
- Git history and working tree contain no token-shaped strings; Railway variables are the only secret store.
